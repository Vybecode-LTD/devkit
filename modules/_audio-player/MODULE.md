# audio-player

> Generated by the Vibrant Mindz backend scaffold (2026-11-15). Status: experimental, nothing built yet. Plan: `docs/plans/vibrant-mindz-backend/backend-plan.md`.

## What it does

One site-wide player with waveforms and a queue, where only one thing plays at a time across every player. Requires kernel only.

## Use when / avoid when

- Use when: The site plays its own audio: albums, singles, beats or readings
- Use when: Several players on one page must never play over each other
- Avoid when: The audio only lives on SoundCloud or Spotify and a provider embed is enough; use embeds

## Settings and env vars

- `autoplay_next` (bool, default `true`): Move to the next item in a queue when one ends
- `count_after_seconds` (int, default `30`): Seconds of listening before a play counts

No env vars; files go through kernel storage.

## Install notes

## Extension points

- Backend `public.py`: nothing yet.
- Web `public.ts`: usePlayerStore (one thing plays at a time), <SpotlightBar>, <AlbumDeck>, <Waveform>, <QueueDock>; SoundCloud tracks play through the widget API behind the same controls.
- Events above; settings above.

## Known limits

- The player never decides what plays: modules hand it items (discography tracks, licensing previews). The homepage's Spotlight, Releases and Videos all register with one store, so starting one pauses the others.
- Raw plays keep 90 days (SPEC 10 retention); `rollup_plays` keeps the daily totals.
