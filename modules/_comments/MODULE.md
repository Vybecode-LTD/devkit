# comments

> Generated by the Vibrant Mindz backend scaffold (2026-11-15). Status: experimental, nothing built yet. Plan: `docs/plans/vibrant-mindz-backend/backend-plan.md`.

## What it does

Threaded discussions under any module's content, with reactions, mentions and approval for guests. Requires `reactions` ^0.1.

## Use when / avoid when

- Use when: Visitors should discuss posts, tracks, beats, artwork or videos
- Use when: Several kinds of content need the same comment threads
- Avoid when: The site wants live chat rooms rather than threads; use community
- Avoid when: Comments would sit on a page nobody reads; leave them off

## What it adds

| Kind | Items |
| --- | --- |
| Routes | API `/api/comments`; public none; member none; admin `/admin/comments` |
| Tables | `comments_thread`, `comments_comment`, `comments_subscription` |
| Slots | `nav.admin`, `admin.dashboard.widget` |
| Permissions | `comments.comment.approve`, `comments.settings.manage` |
| Events | emits: `comments.comment.created`, `comments.comment.approved`; listens: `auth.user.deleted` |
| Notifications | `comments.reply`, `comments.mention` |

## Settings and env vars

- `guest_comments` (bool, default `true`): Guests may comment; every guest comment waits for approval (owner answer Q4)
- `edit_window_minutes` (int, default `15`): Minutes a comment stays editable
- `max_links` (int, default `2`): Links allowed in one comment

No env vars; files go through kernel storage.
