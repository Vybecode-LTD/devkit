# featured

> Generated by the Vibrant Mindz backend scaffold (2026-11-15). Status: experimental, nothing built yet. Plan: `docs/plans/vibrant-mindz-backend/backend-plan.md`.

## What it does

Named slots of ordered, schedulable placements, such as a homepage spotlight or featured products. Requires kernel only.

## Use when / avoid when

- Use when: The homepage or a page shows hand-picked items that staff reorder or schedule
- Use when: Staff need to swap featured content on a date without a deploy
- Avoid when: The list is simply the newest items; query the module that owns them instead
- Avoid when: Each item needs its own fields and pages; build it in its own module

## Known limits

- Slots are declared by the site in seed data (Vibrant Mindz: spotlight, releases, videos). `accepts` lists `<module>.<type>` values or `link`.
- No foreign keys into other modules (SPEC 10). The site's composer skips placements whose item no longer exists and the admin shows them as "This item was removed".
- `announce_boundaries` emits featured.placement.changed when a placement starts or ends, so caches clear on time.
