# roster

> Generated by the Vibrant Mindz backend scaffold (2026-11-15). Status: experimental, nothing built yet. Plan: `docs/plans/vibrant-mindz-backend/backend-plan.md`.

## What it does

A profile per member of a collective, band or team, gathering their work from other modules. Requires kernel only.

## Use when / avoid when

- Use when: The site represents a group whose members each need their own page
- Use when: Members should be able to edit their own profile
- Avoid when: Every signed-up visitor needs a profile; use profiles
- Avoid when: It's a single artist with one about page; use pages

## What it adds

| Kind | Items |
| --- | --- |
| Routes | API `/api/roster`; public `/collective`, `/collective/:slug`; member none; admin `/admin/roster` |
| Tables | `roster_profile`, `roster_link` |
| Slots | `nav.public`, `nav.admin` |
| Permissions | `roster.profile.manage` |
| Events | emits: `roster.profile.published`, `roster.profile.deleted`; listens: `auth.user.deleted` |
| Notifications | none |
