# discography

> Generated by the Vibrant Mindz backend scaffold (2026-11-15). Status: experimental, nothing built yet. Plan: `docs/plans/vibrant-mindz-backend/backend-plan.md`.

## What it does

Albums, tracks, credits and streaming links, with an upload or a SoundCloud link as each track's audio. Requires kernel only.

## Use when / avoid when

- Use when: The site belongs to an artist, band, label or collective that releases music
- Use when: Albums and tracks need their own pages, credits or an on-site player
- Avoid when: Music is only linked out and never played on the site; use embeds
- Avoid when: The audio is a beat or sample for sale; use licensing

## Settings and env vars

- `default_audio_source` (string, default `"upload"`): upload or soundcloud, the default for new tracks
- `stream_bitrate_kbps` (int, default `256`): Bitrate of the public stream file made from an uploaded master
- `show_explicit_badge` (bool, default `true`): Mark explicit tracks in lists and players

No env vars; files go through kernel storage.

- Web `public.ts`: nothing yet.
- Events above; settings above.

## Known limits

- Processing an upload is a kernel job (ffmpeg via run_in_threadpool, or a worker): stream file at `stream_bitrate_kbps`, duration, and about 1,000 waveform peaks. It emits discography.track.processed.
- A track with neither a stream file nor an external URL is not playable: hidden from public lists and flagged in the admin (owner's lens).
- Credits name people as text with an optional roster profile id, so the roster can gather a member's work without a foreign key.
