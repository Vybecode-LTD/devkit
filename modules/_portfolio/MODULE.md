# portfolio

> Generated by the Vibrant Mindz backend scaffold (2026-11-15). Status: experimental, nothing built yet. Plan: `docs/plans/vibrant-mindz-backend/backend-plan.md`.

## What it does

Artwork, design, animation and video pieces grouped by discipline, each optionally linked to a shop listing. Requires kernel only.

## Use when / avoid when

- Use when: The site shows visual work such as paintings, graphic design, animation or video
- Use when: Pieces need their own pages, with credits and an optional buy link
- Avoid when: Pieces are only for sale and need no showcase; use shop
- Avoid when: It's an uncurated photo dump; a gallery block on a page is enough

## What it adds

| Kind | Items |
| --- | --- |
| Routes | API `/api/portfolio`; public `/art`, `/art/:discipline`, `/art/piece/:slug`; member none; admin `/admin/portfolio` |
| Tables | `portfolio_piece`, `portfolio_image` |
| Slots | `nav.public`, `nav.admin` |
| Permissions | `portfolio.piece.manage` |
| Events | emits: `portfolio.piece.published`, `portfolio.piece.deleted`; listens: `auth.user.deleted` |
| Notifications | none |

## Settings and env vars

- `pieces_per_page` (int, default `24`): Pieces on each list page

No env vars; files go through kernel storage.

## Install notes

`devkit add portfolio`. 

## Extension points

- Backend `public.py`: async def piece_cards(db, ids): title, image URL and slug, for roster pages and shop listings.
- Web `public.ts`: <PieceCard>
- Events above; settings above.

## Known limits

- Paintings for sale are shop products (stock 1) that point back to their piece with `shop_product_id`.
