# 0018: The module roadmap after v1.0, and the contract hooks it needs

- **Date:** 2026-11-13
- **Status:** Accepted. Roadmap recorded in `docs/plans/module-roadmap.md`. Hooks applied to SPEC.md so far: none.
- **Context:** On 2026-11-12 a claude.ai session drew up about 140 module ideas the kit doesn't have or plan yet, grouped into 13 categories, plus 12 contract hooks and 7 framework tools. On 2026-11-13 the owner picked each one Must, Want, Later or Nah: 76 Must, 17 Want, 41 Later, 4 Nah. The 12 hooks were left blank, but ten of them are needed by modules the owner marked Must: a site-search module can't search modules that never said what is searchable, and a privacy center can't export data from modules that never said where it lives. Hooks added after v1.0 freezes would be breaking changes for every module already written.
- **Decision:**
  1. **Roadmap.** The Musts become five waves after v1.0 (`docs/plans/module-roadmap.md`), each proven on a real site before the next starts. The owner promoted `maps` and `invoices` to Must so that `directory` and `client-portal` aren't blocked: 78 Must in all. The new Vibrant Mindz site is built from scratch, so it needs no `migrate`; that module stays in the roadmap for client sites. The `sms` module is built as a provider adapter while the owner chooses the provider.
  2. **Hooks.** Ten hooks go into SPEC.md before v1.0 freezes: search index, consent categories, entitlements, bot check, export and erase, content lifecycle, taxonomy, profile tabs, dashboard cards and seed data. Export and erase is already the manifest's `data_hooks` with `export_user_data` / `delete_user_data` (SPEC 5 and 10), so it only gains an export contract test; dashboard cards build on the `admin.dashboard.widget` slot (SPEC 8).
  3. **i18n** is a v1 rule rather than a hook: no hard-coded UI strings. Full translations come later. **Flags** come later, when A/B testing is wanted; module switches cover on and off until then.
  4. Each hook lands in its own PR with the `devkit-hook-designer` skill. That PR adds a change-log line naming this record, adds the hook to a "Hooks every module can fill" index at the end of SPEC 7, and updates the Status line above.
- **Alternatives:** Add each hook when the first module needs it. Rejected: most of those modules arrive after v1.0 freezes, and by then every existing module would need retrofitting. Adding all twelve hooks: i18n and flags have no Must module behind them yet, and the i18n rule gets most of the benefit for none of the cost.
- **Consequences:** v1.0 waits on ten more spec additions, eight of them new, each with its own tests. `module-contract-lint` and `devkit-module-extractor` gain a row or step per hook as it lands. The owner's account copies of those skills need the same edits at the next skill batch (`docs/SKILL-BACKLOG.md`).
