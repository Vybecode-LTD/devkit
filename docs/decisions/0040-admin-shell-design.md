# 0040: The kernel's admin shell is built to the Vibrant Mindz canvas design, styled by tokens

- **Date:** 2026-11-17
- **Status:** Decided; applied in K4. Amends 0008's "the admin shell is VybeSite's, as it stands" (SPEC Q11).
- **Context:** The owner's rule for the Vibrant Mindz site (2026-11-17, through the VM Website session): its admin must look exactly like the canvas **Admin** page, as its public site must look exactly like its boards. The boards are `VM Website/design/site/Admin*.dc.html` (Dashboard, Players, Album, Products, Member, Roles), drawn by `VM Website/design/generators/admin_kit.py` and `build_admin.py`. The brief is `VM Website/design/specs/admin-look.md`. KICKOFF's K4 builds the admin shell before themes, so this had to be decided before K4. Two ways were offered: **A**, build the kernel's admin shell to this design, styled by theme tokens, for every site; **B**, keep VybeSite's shell and let a site replace its frame.
- **Decision** (the owner: "Go with option a and those two conditions"):
  1. **Option A.** K4 builds the kernel's admin shell to the canvas Admin design, styled by theme tokens, as the admin of every DevKit (MechFrame) site. VybeSite's shell supplies behavior to port (accordions, unsaved changes, save conflicts, section history), not its looks.
  2. **Only the generic parts go into the kernel:** the sidebar built from each module's `nav.admin` entries, the top bar, the page header, the owner's "Needs you" list (SPEC 8), cards, tables and forms. Screens that fit only this site (Homepage's Players, Beats) stay with their modules.
  3. **It is checked in both themes,** the site's dark one and the light default (Machined Light), with contrast measured as drawn in each.
- **Alternatives:** *B, a replaceable frame:* two shells to keep looking right, and the kit's parts would have to suit both frames. *VybeSite's shell as it stands (0008):* the site's admin couldn't match its boards.
- **Consequences:** SPEC Q11 changes, with a change-log line. K4's admin shell work starts from the boards and the brief. The Vibrant Mindz mark and palette stay in the site's theme, never in the kernel (the repo is public). The admin and auth screens not drawn yet are designed in the VM Website folder before the step that needs them (the brief lists which). Two related owner rules from the same day: the built site matches the canvas exactly, with no rounding to the theme's scale (`VM Website/design/theme/vibrant-mindz/README.md`, "At K4"), and hosting is Railway, as SPEC already says.
- **See:** decision 0008; SPEC.md 8 and 20 (Q11); `VM Website/design/specs/admin-look.md`
