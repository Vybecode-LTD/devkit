# 0041: Public rendering: one `page()` per address, matched by `routes.public`; the shell, `WEB_DIST` and the kernel's files

- **Date:** 2026-11-17
- **Status:** Applied
- **Context:** SPEC 9 requires every public page to be readable without JavaScript, since GPTBot, ClaudeBot and PerplexityBot run no scripts, and Python can't render React. It gave a module four functions (`head`, `copy`, `structured_data`, `sitemap`) and the kernel `sitemap.xml`, `robots.txt` and `llms.txt`. VybeSite's `site_routes.py`, `spa.py`, `site_html.py` and `routers/sitemap.py` are the pattern (head markers in `index.html`, absolute URLs, a real 404 with noindex, path containment, 503 never 404), and the skill `server-copy-for-crawlers` sums it up; the behavior was ported, not the code. The contract is `dev plans/contracts/k3-public-rendering.md`.
- **Decision** (the owner approved the contract's goal and non-goals, with all five recommended answers):
  1. **One call per page.** A module's `server_copy.py` sets `PAGES` to a `server_copy.Pages` whose `page(db, path, params)` answers a `Page` (title, description, words, JSON-LD, image, Open Graph kind, times, noindex, the canonical's query), a `Moved` (a 301 or 302 to a path on this site) or None (a 404), reading its rows once. `sitemap(db)` lists `Entry`s; one with a title is also a link in `llms.txt`. This replaces SPEC 9's three functions. `InstalledModule(pages=...)` carries it, and the start refuses a module with `routes.public` and no pages, or pages and no `routes.public`.
  2. **Which module answers.** The kernel matches the path against every installed module's `routes.public` and `routes.member` patterns (fixed segments and `:names`): the one with more fixed segments wins, and the start refuses two patterns, in one module or two, that answer the same address at the same rank. A pattern under `/api` or `/admin`, on a kernel file, with a trailing slash or a `.`/`..` segment is refused. Matching is among the modules on: an address only a module that's off takes is a 404, and a module off never keeps an address from one on.
  3. **`/` and the site's identity.** `/` is whichever module declares it. Until one does, or while it's off, the kernel's home page answers: the site's name, its description and its Organization JSON-LD (or `LocalBusiness`, `MusicGroup`, `Person`). The identity is the settings section `kernel.site` (`server_copy.SiteSettings`): description (300), kind, logo and social card (https or a site path), up to 20 profiles, the `llms.txt` summary (2,000) and `ai_crawlers`. The name stays `SITE_NAME`; `server_copy.identity(db)` reads it all.
  4. **AI crawlers allowed by default.** `robots.txt` opens the site to every crawler but `/admin` (anchored, so a public `/administration` stays open) and `/api/`, and names ten AI crawlers in a group of their own, with the same rules, or `Disallow: /` while the site refuses them. `ROBOTS_NOINDEX` keeps its header on every answer.
  5. **nh3 under the builders.** The words come from the kernel's builders (`h1`, `h2`, `h3`, `p`, `ul`, `link`, `time`, `section`, `article`), which escape every value; any text that isn't their `Html` is escaped. A link anywhere unsafe keeps only its words. `cleaned` passes HTML made elsewhere through nh3 without `h1`, and the finished words are cleaned again: no `style`, `script`, event attribute or unsafe link, whatever made them. nh3 is a new, hash-pinned dependency (SPEC 15 already named it for user HTML).
  6. **The kernel serves the built web app.** `WEB_DIST`'s `index.html` is the shell, read at start and refused without its `page-head` and `page-body` markers; unset, a minimal shell with no scripts. Only a file inside the folder is ever served (resolved first, so `..`, an encoded separator, an absolute path or a symlink can't leave it), `/assets/*` immutable for a year, the shell `no-cache`. HEAD is answered as GET without the body, outside the API. The catch-all is registered last and never matches `/api`, so the API's misses stay 404 problem JSON and a wrong method stays 405.
  7. **Every answer.** A page's head has its title, description, an absolute canonical (the page's query, never the request's), Open Graph and Twitter tags with an absolute `og:image` (the page's, else the site's card) and its article times; each JSON-LD object is a data block with `<`, `>` and `&` as JSON escapes. A trailing slash is a 301 without it, query kept. A member page, the admin, a 404 and a 503 get the shell with a plain head: the title, noindex and the site's name. An address with `//`, a backslash or a control character is a 404 before anything else, so no redirect can be turned toward another host. A page whose rows can't be read is a 503 with `Retry-After`; so are the default home page, `robots.txt` (a 5xx keeps crawlers out while the AI switch is unread), `sitemap.xml` and `llms.txt` when theirs can't be. A module's page whose own rows were read still answers when the identity can't be, with the name alone.
  8. **Member pages are noindex, not disallowed.** A member page's shell says `noindex`, which a crawler reads only if robots.txt lets it fetch the page; rules written for member patterns also closed public pages sharing their prefix and missed query-bearing addresses (CodeRabbit on #73). This narrows the approved contract's "member pages disallowed"; the owner confirmed it on 2026-11-17 ("Keep noindex").
  9. **The kernel's files**, generated per request from the modules on: `sitemap.xml` (the kernel's home page when it answers `/`, then each module's entries that aren't `noindex` and that its own public pattern answers; 50,000 at most, the rest logged), `robots.txt`, and `llms.txt` (llmstxt.org: name, description, summary, a section per module; 500 links at most).
- **Alternatives:** *SPEC 9's three functions:* each would read the same rows again, or a module would cache between calls. *First `head()` that isn't None wins (the skill):* order-dependent and silent when two modules claim one address; ranked patterns checked at start make the winner certain. *A module owns `/` always:* a site with no such module would answer 404 at its own address. *robots.txt's AI crawlers in the `*` group:* a site couldn't refuse them without refusing search engines. *Serve `index.html` as built when it lacks the markers (VybeSite):* a site would ship pages with the wrong head and never know; the start refuses instead. *A noindex flag found by asking every page:* the sitemap would read every page's rows on each request; `Entry(noindex=)` lets the module mark the same rows it marks on the page.
- **Consequences:** SPEC 6, 7 and 9 change, with a change-log line. No migration: the identity is a row in `kernel_setting`. K4 mounts its React shell with `createRoot` and styles or hides `[data-server-copy]`, and adds the Playwright parity test with its first React page; K5's site template sets `WEB_DIST` to its build. A redirects module, per-page meta editing, other sitemaps, hreflang and caching of rendered pages come later or never (the contract's non-goals).
