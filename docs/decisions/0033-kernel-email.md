# 0033: Kernel email: templates a site can reword, and SMTP first, Resend only where SMTP is blocked

- **Date:** 2026-11-16
- **Status:** Applied
- **Context:** K3's second service (decision 0029). Decision 0013 kept `email.send(template, to, context)` as the public API, with K2's `Mailer` beneath it, and SPEC 2 listed one adapter, "SMTP, Mailgun or Resend", to be chosen in K3. Railway blocks outbound SMTP on its Hobby plan (open on Pro), so a site there needs a provider's HTTPS API. The owner approved the contract (`dev plans/contracts/k3-email.md`) on 2026-11-16, chose Resend as the HTTPS adapter, then set the rule: SMTP is the first option, and Resend is used only where the host doesn't support SMTP, chosen at setup.
- **Decision:**
  1. **Templates** are `email.Template(subject, text, html=None)` in `string.Template` syntax (`$name`, `${name}`, `$$`), so there's no template engine to add and nothing in a template can run code. A module declares its own in `backend/<id_>/emails.py`'s `EMAILS`, each named `<id>.<name>`; the harness and `devkit add` pass them as `InstalledModule(emails=...)`.
  2. **A site rewords** any declared template through `create_app(emails=...)`, using only the placeholders the original uses, since the senders don't pass any other. `create_app` checks every template and refuses to start on a name outside its module, an unknown rewording, a stray placeholder, a subject on two lines, or a `$` that starts no placeholder.
  3. **Rendering** adds `site_name` and `site_url`; a context can't set them. In the subject, each value is folded onto one line, line breaks and control characters included; in the HTML, each is escaped; the text body takes them as given. A missing value is ValueError naming the template and the placeholder, never a value. `Checked` still guards every message after.
  4. **Adapters, SMTP first** (the owner's rule). With `SMTP_HOST` set, mail goes out by SMTP: the standard library's `smtplib` off the event loop, implicit TLS on 465 and STARTTLS on any other port, certificates checked, a 15-second timeout. Only where the host blocks SMTP is `RESEND_API_KEY` set instead, without `SMTP_HOST`: Resend's `POST /emails` over httpx with a 10-second timeout. Both set: SMTP, with a warning that the key is unused. Neither: nothing is sent (`LogMailer`). There's no variable to pick Resend where SMTP works. No new dependency. The From header is `MAIL_FROM_NAME` (default `SITE_NAME`) and `MAIL_FROM`, built by `formataddr`, with an international domain in IDNA; a local part beyond ASCII is refused rather than mangled.
  5. **Failures** are `MailError`, with `retryable` and `retry_after`. Resend's 400, 401, 403, 409 and 422 aren't retryable; 429 and 5xx are, as its docs say. SMTP's 4xx replies and a lost connection are retryable; 5xx, a refused login and a server without STARTTLS aren't. No message holds the address, the subject, the body or a credential; Resend's error name is kept, its message (which can repeat the address) isn't.
  6. **Config.** `MAIL_FROM`, `MAIL_FROM_NAME`, `SMTP_HOST`, `SMTP_PORT` (587), `SMTP_USERNAME`, `SMTP_PASSWORD` and `RESEND_API_KEY`, the secrets as `SecretStr`. Mail set in part (an address or an SMTP login with neither `SMTP_HOST` nor a Resend key, a blank `MAIL_FROM`, half a login), a `MAIL_FROM` that isn't one bare address, or a placeholder domain in it stops the start outside DEBUG; with DEBUG on, mail goes to `LogMailer` instead.
  7. **`send` is global, like `storage`:** `create_app` installs the mailer and the templates, and a worker will call `email.install` itself. The latest app's are the ones used.
- **Alternatives:** *Jinja2 templates:* a new dependency and a template language that can do more than a mail needs. *Template files found on disk:* modules are copied into sites, but the kernel has no package path for a module; a fixed-name attribute is how `CSP` and `Settings` are found already (decision 0009). *Mailgun:* VybeSite already uses it, but its setup is heavier and its free tier smaller; it can follow when a site needs it. *SMTP only:* blocked on Railway's Hobby plan. *A `MAIL_ADAPTER` variable to pick either:* it would let a site use Resend where SMTP works, against the owner's rule. *Falling back to Resend at send time when SMTP can't connect* (the owner's other option): on a blocked host every mail would wait out the SMTP timeout first; the owner chose setup. *aiosmtplib:* a dependency for what `smtplib` in a thread does.
- **Consequences:** SPEC 2's email row, section 4's module layout, section 7's fixed names and section 6's `email.send` row change, with a change-log line. K2's auth mails moved onto `kernel.*` templates in #60 (`kernel/auth/mails.py`, 19 of them; contract `dev plans/contracts/kernel-auth-templates.md`), word for word, so a site rewords them like a module's. Retries arrive with K3's jobs, which read `MailError.retryable`. A live site needs the owner's Resend account, a verified sending domain, and `RESEND_API_KEY` typed into the host's variables.
