# 0032: Kernel storage: two buckets, short signed links, downloads by default, and moto for the tests

- **Date:** 2026-11-16
- **Status:** Applied
- **Context:** K3 starts with storage (decision 0029), since the Vibrant Mindz modules keep masters, stream files, licensed files and photos in it (`docs/plans/vibrant-mindz-backend/kernel-additions.md`, item 3). SPEC 6 named `storage.put / get / signed_url`, SPEC 2 boto3 against an S3-compatible store (Cloudflare R2), and SPEC 15 the rules: private files only through short-lived signed links, a provider's file on a public, unguessable link that expires with its job, and anything that isn't an image served as a download. The owner approved the contract (`dev plans/contracts/k3-storage.md`) on 2026-11-16.
- **Decision:**
  1. **Two buckets** (the owner's approval). `STORAGE_BUCKET` is private. `STORAGE_PUBLIC_BUCKET` is optional and served to anyone at `STORAGE_PUBLIC_URL` (on R2, the bucket's custom domain), for stream files and photos. R2 makes a whole bucket public or none of it, so a second bucket is how private files can never be public, and how public files keep fixed addresses a browser and a CDN can cache.
  2. **A provider's file** goes in the public bucket under `unguessable_key` (a 192-bit random segment), and its module deletes it when the job ends. A signed link can't do this job: SigV4 links last a week at most, and an order can last longer.
  3. **Signed links** are for the private bucket only, live 5 minutes unless asked, and never more than 6 hours (long enough for a film played by range requests). Every one signs `Content-Disposition: attachment` in, so whoever holds it can't strip it; `<img>`, `<audio>` and `<video>` still play it.
  4. **Inline only for PNG, JPEG, GIF, WebP and AVIF** whose first bytes match their type; a claimed image whose bytes don't match is refused. Everything else, SVG included, is stored as an attachment, so an uploaded page or script never renders on the store's address.
  5. **The API:** `put`, `get`, `download`, `delete`, `signed_url`, `public_url`, `unguessable_key` and `check_key` (the contract has the signatures). `download` streams big files (a job feeding ffmpeg); `get` refuses a file over its `max_bytes` (32 MiB unless asked) before reading it. Keys are `/`-separated segments of letters, digits, `.`, `_` and `-`, none starting with `.`, at most 512 characters; a module's keys start with its id.
  6. **boto3 runs off the event loop** (`asyncio.to_thread`), with path-style addressing, SigV4, region `auto`, checksums only when an operation requires them, a 5-second connect and 60-second read timeout, and three tries in all. The endpoint is cut back to scheme, host and port, so a pasted bucket URL still works (Basefra.me's lesson).
  7. **Off until set.** With no `STORAGE_*` variable set, every call raises `StorageNotConfigured`, naming the variables. Set in part, `refuse_unsafe` stops the start outside DEBUG, as it does for an unsafe secret: a missing endpoint, key or bucket, an endpoint or public URL that isn't https, a public bucket without its URL or the reverse, or one bucket named twice. The secret is a `SecretStr`, and no message holds a value.
  8. **Tests** (the owner's choice, 2026-11-16): moto, an S3 inside the test process, for the suite: nothing to run and no CI minutes. moto signs links but never checks them, so `kernel/tests/test_storage_live.py` fetches real links (the signature, a tampered link, expiry, a public file, a deleted file) against a real store when `TEST_STORAGE_*` names one, and is skipped otherwise.
- **Alternatives:** *One bucket, public files through signed links too:* links that change with every page view, which browsers and a CDN can't cache. *One bucket, made public:* every private file would be one guessed key away. *A local MinIO for the tests:* its community edition stopped publishing images in October 2025 and is source-only now; any local server costs a service on the owner's machine and CI minutes on every run, and still isn't R2. *aiobotocore:* another dependency for what `to_thread` does; Basefra.me runs the same way.
- **Consequences:** boto3 joins `requirements.in` and moto `requirements-dev.in`, both hash-pinned and audited. SPEC 6's storage row and SPEC 15's object storage line change, with a change-log line. A site needs the owner's R2 set-up before its first upload: two buckets, a custom domain on the public one, and one API key for both, typed into the host's variables. Uploads straight from the browser, type detection beyond the inline check, and Pillow re-encoding come with the modules that need them (the contract's non-goals).
